## Решение

Для решения задачи была выбрана структура данных CuncurrentSkipList.
### Описание:
Skip List — это вероятностная структура данных, использующая несколько уровней связанных списков для обеспечения быстрого поиска, вставки и удаления элементов, сравнимого с производительностью сбалансированных деревьев поиска, но с более простой реализацией.

### Concurrent Skip List
#### Подход к созданию Concurrent Skip List:
1) CAS (Compare and Swap): Атомарная операция, которая сравнивает значение переменной с ожидаемым значением и, если они совпадают, устанавливает новое значение. Используется для атомарного обновления указателей.

2) Атомарные ссылки (AtomicReference, AtomicMarkableReference): Классы, предоставляющие атомарный доступ к ссылкам на объекты. AtomicMarkableReference также позволяет "помечать" ссылку, что полезно для логического удаления узлов.

### Структура Cuncurrent Skip List
#### 1. Узел (Node):

Каждый узел в Skip List содержит:

1) key (ключ): Значение элемента, по которому производится поиск и сравнение.

2) next (массив указателей): Массив указателей на следующий узел на каждом из уровней, на которых присутствует данный узел. Размер массива next определяет "высоту" узла.

```java
    public class Node {
    final Integer key;
    // Массив ссылок, на каждом уровне своя атомарная ссылка.
    final AtomicMarkableReference<Node>[] next;

    // Макс уровень
    static final int MAX_LEVEL = 16;

    public Node(int key, int height) {
        this.key = key;
        @SuppressWarnings("unchecked")
        AtomicMarkableReference<Node>[] tmp =
                (AtomicMarkableReference<Node>[]) new AtomicMarkableReference[height + 1];
        for (int i = 0; i <= height; i++) {
            tmp[i] = new AtomicMarkableReference<>(null, false);
        }
        this.next = tmp;
    }

    public int getHeight() {
        return next.length - 1;
    }

    @Override
    public String toString() {
        return "Node{" + "key=" + key + ", height=" + getHeight() + '}';
    }
}
```

#### 2) Уровни Skip List:

Skip List состоит из нескольких уровней связанных списков.

1) Уровень 0 (Базовый уровень): Стандартный отсортированный связанный список, содержащий все элементы Skip List.

2) Вышележащие уровни: Каждый следующий уровень является "экспресс-версией" предыдущего, содержащей подмножество элементов. Вероятность того, что узел будет присутствовать на более высоком уровне, уменьшается.

#### 3. Вероятностное определение высоты узла:
При вставке нового элемента его "высота" (количество уровней, на которых он будет присутствовать) определяется случайным образом. Обычно используется вероятность p = 0.5, то есть при "подъеме" на следующий уровень вероятность присутствия узла составляет 50%.

### Основные Методы Skip List

#### 1. Search (Поиск):
Алгоритм поиска начинается с верхнего уровня заголовочного узла.

1) Начать поиск с самого высокого уровня, где присутствует заголовочный узел.

2) Пока ключ следующего узла на текущем уровне меньше искомого ключа, перемещаться вправо по этому уровню.

3) Если ключ следующего узла больше или равен искомому ключу, или достигнут конец уровня, спуститься на один уровень ниже и повторить шаг 2.

4) Поиск продолжается до базового уровня (уровень 0), где искомый элемент (если он присутствует) будет находиться непосредственно после последнего пройденного узла.

```java
public boolean search(int key) {
        Node current = head;
        for (int level = Node.MAX_LEVEL; level >= 0; level--) {
            boolean[] markHolder = {false};
            Node next;
            while (true) {
                next = current.next[level].getReference();
                markHolder[0] = current.next[level].isMarked();
                if (next == null) break;
                if (markHolder[0]) {
                    // Если помечена ссылка, значит узел логически удалён, уходим
                    break;
                }
                if (next.key < key) {
                    current = next;
                } else {
                    break;
                }
            }
        }
        current = current.next[0].getReference();
        return (current != null && current.key == key && !current.next[0].isMarked());
    }
```

#### 2. Insert (Вставка):
    
1) Случайное определение уровня.

2) Выполняется поиск места вставки, как и в обычной Skip List, но при этом используются атомарные операции для чтения указателей.

3) Создание узла.

4) Атомарно обновляются указатели next предыдущих узлов на каждом уровне, чтобы указать на новый узел. Может потребоваться несколько попыток в случае конкуренции (цикл CAS).

```java   
                Node succ = succs[level];
                newNode.next[level].set(succ, false);
            }

            // Сшиваем предшественников с новым узлом
            for (int level = 0; level <= newLevel; level++) {
                Node pred = preds[level];
                Node succ = succs[level];
                while (true) {
                    // Читаем текущее состояние
                    boolean[] markHolder = {false};
                    Node ref = pred.next[level].get(markHolder);
                    // Проверяем, что пред всё ещё указывает на succ
                    if (!markHolder[0] && ref == succ) {
                        // CAS: если успешно, идём дальше
                        if (pred.next[level].compareAndSet(succ, newNode, false, false)) {
                            break;
                        }
                    } else {
                        // если CAS не прошёл — пересобираем preds и succs и начинаем заново
                        find(key, preds, succs);
                        break;
                    }
                }
            }
            // Увеличиваем size (без блокировки)
            size.incrementAndGet();
            return true;
        }
    }
```
#### 3. Remove (Удаление):

1) Поиск удаляемого узла.

2) Логическое удаление (маркировка): Узел помечается как удаленный с помощью AtomicMarkableReference.

3) Физическое удаление (обход): На каждом уровне указатели next предыдущих узлов атомарно обновляются, чтобы "пропустить" помеченный узел. Это может происходить асинхронно.

```java
public boolean remove(int key) {
        Node[] preds = new Node[Node.MAX_LEVEL + 1];
        Node[] succs = new Node[Node.MAX_LEVEL + 1];
        Node nodeToRemove;
        boolean isMarked;

        while (true) {
            boolean found = find(key, preds, succs);
            if (!found) {
                return false; // нет такого ключа
            }
            nodeToRemove = succs[0];

            // Помечаем все уровни выше 0
            for (int level = nodeToRemove.getHeight(); level >= 1; level--) {
                boolean[] markHolder = {false};
                Node succ = nodeToRemove.next[level].get(markHolder);
                while (!markHolder[0]) {
                    nodeToRemove.next[level].attemptMark(succ, true);
                    succ = nodeToRemove.next[level].get(markHolder);
                }
            }

            // Помечаем 0-й уровень
            boolean[] markHolder = {false};
            Node succ = nodeToRemove.next[0].get(markHolder);
            while (true) {
                isMarked = nodeToRemove.next[0].compareAndSet(succ, succ, false, true);
                succ = nodeToRemove.next[0].get(markHolder);
                if (isMarked) {
                    size.decrementAndGet();
                    // «откусываем» узел из skip list
                    find(key, preds, succs);
                    return true;
                } else if (markHolder[0]) {
                    // уже помечен
                    return false;
                }
            }
        }
    }
```

### Вывод:
#### 1) Операция insert
1) При увеличении потоков insert даёт рост throughput.

2) Прирост от 4 потоков к 8 примерно в 1,5–2 раза, что подтверждает, что skip list умеет параллелить операции вставки.

3) При большом DataSize (100k) однопоточный insert даёт низкий throughput (~0.93 ops/ms), но при 8 потоках получаем неплохие результаты ~9.8 ops/ms.

#### 2) Операция remove
1) Операция remove показывает очень большие числа при небольшом DataSize и большом числе потоков. Это может указывать на то, что большая часть вызовов быстро «пролетает» (элемент уже удалён или отсутствует).
2) Большой разброс (50к 8 потоков) может возникнуть из-за того, что в разных итерациях потоки могут «случайно» чаще наткнуться на несуществующие элементы 
(операция завершается мгновенно) или же на ещё существующие.
3) При DataSize = 100k в 8 потоках ~9.56 ops/ms (но с разбросом ±17.7). В любом случае, это выше, чем значение на 4 потоках, что подтверждает масштабирование.
